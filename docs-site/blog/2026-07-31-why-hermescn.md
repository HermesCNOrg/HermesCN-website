Hermes Agent 已经不只是一个聊天工具。它可以读写文件、调用工具、保留记忆，也可以通过消息平台和定时任务长期运行。

但从“听说过 Hermes”到“让它稳定地完成工作”，中间还有一段不短的路。HermesCN 就是为这段路创建的。

<!-- truncate -->

## 我们看到的问题

Hermes 更新很快，主要资料又以英文为主。中文用户即使完成安装，往往还会遇到更实际的问题：任务应该怎样描述，结果如何验证，哪些权限可以交给 Agent，失败后怎样停止和恢复。

有价值的经验也很分散。一个好用的 Skill、一套可靠的工作流，可能只存在于 GitHub 仓库、社交平台或某次聊天记录里。下一次遇到相似问题，很多人仍然需要从头摸索。

企业面临的是另一类困难。它们通常不缺少对 Agent 的兴趣，缺少的是判断和落地：哪些流程值得改造，怎样接入已有系统，数据与权限如何管理，上线后由谁维护。

这些问题无法靠翻译几篇文档解决。

## HermesCN 想做什么

HermesCN 是围绕 Hermes Agent 建设的中文社区与行业服务网络。

面向个人，我们维护中文文档和实践教程，整理 Skills、工作流与真实案例。目标很具体：帮助第一次接触 Hermes 的人完成首个任务，也让长期使用者能把有效经验沉淀下来，继续参与项目、开源贡献或职业实践。

面向企业，我们从业务问题开始，判断 Agent 是否适合，再推进原型验证、系统集成和持续优化。一个能演示的 Demo 还不够，交付结果需要有明确边界、验收标准和维护责任。

社区与企业服务并不是两套互不相干的工作。成员在实践中形成能力，进入真实项目解决问题；项目中的约束和失败经验经过授权与脱敏，又可以回到教程、案例和工具库。

## 我们希望补上的距离

官方文档负责说明 Hermes 有哪些能力和参数。HermesCN 的教程更关心怎样开始、为什么这样做、如何确认成功。

我们会持续做几件事：

- 同步并校验中文文档，尽量保留命令、链接和技术结构；
- 用真实任务组织教程，让安装之后有路可走；
- 把零散经验整理成可以复用的 Skills、工作流和案例；
- 为企业提供场景判断、原型验证与落地协作；
- 给中文用户提供参与测试、文档和开源贡献的入口。

## 有些边界必须说清楚

HermesCN 不是 Nous Research 或 Hermes 官方团队，也不代表它们作出承诺。

我们不会把一次 Demo 包装成成熟方案，也不会把未经验证的体验写成确定事实。涉及 Hermes 的能力、命令和参数，以最新官方文档和实际验证为准。

Agent 可以承担越来越多的执行工作，但发布、付款、凭据、安全边界和不可逆操作，最终决定权仍然属于人。

## 接下来

HermesCN 现在已经有中文文档、18 篇入门教程、Skills 目录和社区入口。接下来，我们会继续补充可复现的实践案例，让更多经验不再停留在聊天记录里。

如果你正在学习 Hermes，可以从[从入门到精通](/tutorials/)开始。如果你已经在使用它，也欢迎把遇到的问题、失败记录和有效方法带到 [GitHub](https://github.com/HermesCNOrg)。

HermesCN 要做的事情并不神秘：让中文用户少走一些弯路，让真正有效的方法留下来。
